# Техническое задание

## Локальный распределённый менеджер файлов (P2P Share без интернета)

**Версия документа:** 1.0  
**Статус:** каркас проекта, реализация сети и доводка UI — по командным веткам  
**Стек:** Python 3.10+, PyQt6, стандартная библиотека (`socket`, `hashlib`, `json`)

---

## 1. Проблема

В учебных аудиториях, лабораториях и на офлайн-мероприятиях студентам нужно быстро обменяться файлами (отчёт, презентация, датасет), но:

- нет стабильного доступа в интернет или он запрещён политикой сети;
- облачные диски и мессенджеры недоступны;
- общая сетевая папка часто отсутствует, требует прав администратора или «светит» файлы всем сразу;
- флешки неудобны, теряются и не дают контроля целостности.

Нужен **локальный P2P-обмен в пределах одного LAN/Wi‑Fi**: узлы сами находят друг друга, передают файл по частям и проверяют, что байты не повреждены.

---

## 2. Целевая аудитория

| Группа | Зачем продукт |
|---|---|
| Студенты на паре / в общежитии | Обмен материалами без интернета |
| Учебные лаборатории | Раздача одного файла нескольким ПК в одной подсети |
| Преподаватель (как проверяющий сценарий) | Демонстрация архитектуры, устойчивости и командной работы в Git |

Продукт **не** рассчитан на публичный интернет, NAT traversal, DHT и анонимные сети.

---

## 3. Цель и результат

Разработать настольное приложение, которое:

1. Обнаруживает соседей в локальной сети (UDP discovery).
2. Передаёт файлы по TCP **чанками** с отображением прогресса.
3. Проверяет целостность **SHA-256**.
4. Корректно обрабатывает обрыв сети (сообщение пользователю, возможность возобновления).
5. Имеет современный GUI на PyQt6 (список онлайн-пользователей, drag-and-drop, progress bar).

---

## 4. Функциональные требования

### 4.1. Обязательные (must)

| ID | Требование | Модуль |
|---|---|---|
| F1 | Пользователь задаёт отображаемое имя (или берётся из конфигурации/ENV) | `core.config`, UI |
| F2 | Узел периодически объявляет себя в LAN широковещательным UDP-пакетом `HELLO` | `network.discovery` |
| F3 | Список «онлайн» обновляется; узел без `HELLO` дольше TTL исчезает | `network.peer_registry` |
| F4 | Пользователь выбирает соседа и файл (кнопка или drag-and-drop) | `ui` |
| F5 | Передача идёт по TCP порциями фиксированного размера (`chunk_size`) | `network.transfer` |
| F6 | Получатель собирает чанки во временный `.part` файл, затем сохраняет в каталог загрузок | `core.session` |
| F7 | После сборки считается SHA-256 и сверяется с манифестом | `core.hashing`, `core.integrity` |
| F8 | Progress bar отражает процент (`bytes_done / size`) | `ui.progress_panel` |
| F9 | Обрыв TCP (таймаут, reset, потеря Wi‑Fi) не роняет процесс: статус `interrupted` + текст ошибки | `core.errors`, `core.session` |
| F10 | Повторная отправка/приём с того же offset (resume), если `.part` сохранился | `core.session.resume_offset` |
| F11 | Некорректный пакет UDP/TCP логируется и отбрасывается, приложение продолжает работу | `network` |

### 4.2. Желательные (should)

| ID | Требование |
|---|---|
| F12 | Несколько одновременных передач в списке прогресса |
| F13 | Отказ от файла получателем (`FILE_REJECT`) |
| F14 | Отображение хеша в UI после успешной проверки |
| F15 | Выбор каталога сохранений |

### 4.3. Не входят в must (could / later)

- Передача папок целиком как архива.
- Шифрование канала (TLS) — вне учебного LAN-сценария.
- Релей через интернет, STUN/TURN, IPv6-only mesh.

## 5. Нефункциональные требования

| ID | Категория | Требование |
|---|---|---|
| N1 | Архитектура | Три независимых пакета: `network/`, `core/`, `ui/` + тонкий фасад `app/controller.py`. UI **не** импортирует `socket`. |
| N2 | Командная работа | Члены команды ведут разные Git-ветки (`feature-network`, `feature-ui`, при необходимости `feature-core`) без правки одних и тех же файлов без нужды |
| N3 | Надёжность | Все ожидаемые сбои сети и диска — через иерархию `P2PShareError`; GUI ловит базовый тип |
| N4 | Целостность | Несовпадение SHA-256 чанка или файла — `IntegrityError`, файл не выдаётся как успешный |
| N5 | Производительность | Чанк по умолчанию 64 КиБ; хеш считается потоково, файл не обязан целиком лежать в RAM |
| N6 | Переносимость | Windows / Linux, Python 3.10+, без внешних облачных API |
| N7 | Наблюдаемость | `logging` в консоль: discovery, connect, chunk, interrupt, verify |
| N8 | Тестируемость | Юнит-тесты на хеш, протокол, TTL реестра, обрыв сессии (`pytest`) |
| N9 | UX | Тёмная тема, читаемые статусы на русском, drag-and-drop |
| N10 | Безопасность (учебная) | Только LAN; нет удалённого выполнения; принимаются только файлы, инициированные пользователем |

## 6. Границы проекта

**Входит:**

- Обнаружение пиров в одной широковещательной подсети.
- Точка-точка передача файла.
- Проверка SHA-256.
- GUI PyQt6.
- Документация (этот файл, README, GIT_GUIDE).

**Не входит:**

- Работа через интернет, VPN как обязательное требование, NAT hole punching.
- Центральный сервер каталогов.
- Синхронизация каталогов «как Dropbox».
- Мобильные клиенты, веб-клиент.
- DRM, антивирусная проверка содержимого.
- Авторизация в домене Active Directory.

**Ограничения среды:**

- Требуется, чтобы ОС не резала UDP broadcast и входящий TCP выбранных портов (по умолчанию 37020 / 37021).
- Два клиента на одной машине: сменить порты через `P2P_UDP_PORT` / `P2P_TCP_PORT`.

## 7. Архитектура (для проверки преподавателем)

```
┌─────────────────────────────────────────────┐
│                   ui/                       │
│  MainWindow, PeerList, DropZone, Progress   │
└──────────────────┬──────────────────────────┘
                   │ только ApplicationController
┌──────────────────▼──────────────────────────┐
│              app/controller.py              │
└──────┬──────────────────────────────┬───────┘
       │                              │
┌──────▼──────────┐          ┌────────▼────────┐
│    network/     │          │      core/      │
│ UDP discovery   │          │ SHA-256, модели │
│ TCP chunks      │          │ ошибки, сессия  │
│ protocol, peers │          │ resume, config  │
└─────────────────┘          └─────────────────┘
```

Контракт между слоями — датаклассы `PeerInfo`, `FileManifest`, `TransferProgress` и исключения `P2PShareError`.

---

## 8. Протокол (кратко)

**UDP HELLO (JSON):** `peer_id`, `display_name`, `tcp_port`, `protocol_version`.

**TCP-кадр:** 8 ASCII-цифр длины + JSON-тело (`type`, `protocol_version`, `payload`).

Типы: `hello`, `file_offer`, `file_accept`, `file_reject`, `chunk`, `chunk_ack`, `resume`, `complete`, `error`.

Чанк сопровождается индексом и SHA-256 полезной нагрузки (реализуется в `feature-network`).

## 9. Критерии приёмки (проверяемые)

Преподаватель / команда считает функцию принятой, если выполняется **конкретный сценарий**.

| ID | Сценарий приёмки | Ожидаемый результат |
|---|---|---|
| A1 | Запуск `python main.py` на ПК с PyQt6 | Окно открывается, нет traceback |
| A2 | Два экземпляра в одной LAN (или два ПК) | Имена появляются в списке «Онлайн» не позже ~TTL |
| A3 | Drag-and-drop файла + «Отправить» | Progress bar движется, на приёмнике файл в `received_files/` |
| A4 | Сравнить SHA-256 исходника и копии | Хеши совпадают; в логе статус verifying → completed |
| A5 | Выдернуть кабель / оборвать Wi‑Fi на середине | Процесс жив, статус interrupted, текст ошибки, байты учтены |
| A6 | Повторить передачу того же файла | Продолжение с `resume_offset` либо корректный новый старт |
| A7 | Подменить байт в `.part` до финальной проверки | `IntegrityError`, файл не помечается completed |
| A8 | `pytest` | Тесты каркаса зелёные |
| A9 | Структура репозитория | Есть `network/`, `core/`, `ui/`, `TZ.md`, `README.md` |
| A10 | GitHub | Ветка `main`, feature-ветки, **merge-коммиты** (не только fast-forward), осмысленные сообщения |

Каркас (текущее состояние репозитория) закрывает A1, A8, A9 и контракты для A2–A7. Сетевая логика сокетов — критерий готовности ветки `feature-network`.

## 10. Распределение ролей (рекомендуемое)

| Студент | Ветка | Зона ответственности | Файлы (чтобы не конфликтовать) |
|---|---|---|---|
| A | `feature-network` | UDP/TCP сокеты, цикл чанков, ACK | `p2pshare/network/*.py` (кроме стабильного контракта в `protocol.py`, его менять согласовывая) |
| B | `feature-ui` | полировка GUI, диалоги, UX ошибок | `p2pshare/ui/*.py` |
| C (опционально) | `feature-core` | resume на диск, очередь передач | `p2pshare/core/session.py`, тесты |

Фасад `app/controller.py` меняют только по договорённости (маленький PR).
